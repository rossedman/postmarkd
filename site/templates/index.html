Sending mail should be one line.

postmarkd is a small daemon that sits next to your apps, on a server or as a container sidecar, and delivers their mail through Postmark. Use HTTP, SMTP, sendmail or the CLI. Your Postmark token stays in one place.

How it works

Every way in. One way out.

Whatever your software speaks, postmarkd turns it into the same validated, rate-limited Postmark API call, over pooled connections and with retries that never send a message twice.

  • sendmailcron, mail, PHP mail(), git
  • SMTPRails, Django, Laravel, Grafana
  • HTTPPostmark SDKs, curl, any HTTP client
  • CLIshell scripts, CI jobs, alerts

Features

Small daemon. Everything you need.

Postmark-compatible API

The same endpoints and JSON as Postmark: /email, batches, templates. Existing SDKs work by changing the base URL.

SMTP and sendmail

A local SMTP listener and a drop-in sendmail. MIME, attachments, inline images and X-PM-* headers handled.

Blackhole for tests

Accept everything, send nothing, answer like Postmark. Tests read back what was “sent”. No account, no network.

Message streams

Receipts on outbound, newsletters on broadcast, per message or per request, even mixed in one batch.

Built for volume

500-message batches, a concurrency limit, pooled keep-alive connections and a bounded queue with back-pressure.

DKIM, SPF, DMARC check

postmarkd check-domain tells you which DNS records are missing, and the exact values to add.

systemd native

Socket activation (even port 25, unprivileged), readiness, watchdog, graceful drain and a hardened unit.

Sidecar ready

A 16 MB non-root image with a built-in health check. Compose, Kubernetes and CI examples included.

Observable

Prometheus metrics for every endpoint and Postmark call, health and readiness checks, structured logs.

33,700messages per second end to end over the unix socket on 4 CPUs
4.4 µsto validate and apply defaults to a message

Install

Running in a minute.

# Debian / Ubuntu (for Fedora, RHEL: dnf install the .rpm; see the docs)
$ VERSION={{.Version}} ARCH=$(dpkg --print-architecture)
$ REL=https://github.com/rossedman/postmarkd/releases/download/v$VERSION
$ curl -fsSLO $REL/postmarkd_${VERSION}_linux_$ARCH.deb
$ sudo apt install ./postmarkd_${VERSION}_linux_$ARCH.deb

$ sudo install -m 0600 /dev/stdin /etc/postmarkd/server-token <<< 'your-server-token'
$ sudo systemctl enable --now postmarkd

$ echo "Hello from $(hostname)" | postmarkd send -to you@example.com -subject "It works"
$ docker run -d --name postmarkd \
    -p 127.0.0.1:8025:8025 -p 127.0.0.1:2525:2525 \
    -e POSTMARKD_SERVER_TOKEN=your-server-token \
    -e POSTMARKD_DEFAULT_FROM=noreply@yourdomain.com \
    ghcr.io/rossedman/postmarkd:{{.Minor}}

$ curl localhost:8025/email -d '{"To":"you@example.com","Subject":"Hi","TextBody":"Hello"}'
# A native sidecar: starts before your app, stops after it.
initContainers:
  - name: postmarkd
    image: ghcr.io/rossedman/postmarkd:{{.Minor}}
    restartPolicy: Always
    env:
      - { name: POSTMARKD_LISTEN, value: 127.0.0.1:8025 }
      - name: POSTMARKD_SERVER_TOKEN
        valueFrom: { secretKeyRef: { name: postmark, key: server-token } }
# GitHub Actions: a fake Postmark for your integration tests
services:
  postmarkd:
    image: ghcr.io/rossedman/postmarkd:{{.Minor}}
    env: { POSTMARKD_BLACKHOLE: "true" }
    ports: [ "8025:8025", "2525:2525" ]

# then, in a test step:
$ curl -s localhost:8025/blackhole/messages | jq '.Messages[].Message.Subject'

Why postmarkd

Why not call Postmark directly?

For one app with a Postmark SDK, you should. postmarkd helps when mail comes from many places, or from places that can’t easily talk to Postmark.

Postmark directlyWith postmarkd
Server tokenCopied into every app, container and CI secretIn one place. Apps get nothing, or their own revocable token
cron, PHP mail(), mailxConfigure Postfix as an authenticated TLS relaySymlink postmarkd as sendmail
SMTP-only appsPostmark's SMTP host, TLS and credentials in eachlocalhost:2525, nothing else
Tests and CITest token: needs network, can’t read back mailBlackhole mode: offline, assert on what was sent
LatencyEvery send waits on the Postmark round tripLocal socket, or ?async=true returns immediately
Defaults and rulesRepeated in each appSet once for the host
